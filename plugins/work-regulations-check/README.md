# work-regulations-check

日本の就業規則を **作る** ための Claude Code プラグイン。スキルが2つ入っています。

| スキル | 何をするか |
|---|---|
| **work-regulations-draft** | 厚生労働省「モデル就業規則」の規程例をもとに、事業場の実情を聞き取って就業規則を作成する |
| **work-regulations-check** | 既存の就業規則を労働基準法などの法令に照らして点検する |

どちらを使うかは話しかけ方で決まります。「就業規則を作りたい」なら作成側、
「この規程をチェックして」なら点検側が動きます。

---

## 作成（work-regulations-draft）

厚生労働省の規程例を条文の供給元にして、**条文を創作しません**。
事業場の実情を聞き取り、規程例から選んで数値と固有名詞を埋めます。

聞き取りは3段階に分けます。一度に全部聞くと答えが返ってこないためです。

1. これが無いと条文が書けないもの（会社名、労働者数、労働時間、休日、賃金の締切と支払日など）
2. 制度の有無だけ（賞与、退職金、休職、定年、副業、テレワーク…）
3. 「ある」と答えた制度の細目

**決まらない項目は推測で埋めず、保留にします。** 「〇日」のまま納品された規程が
そのまま運用される事故を防ぐためです。保留は「決める必要がある項目」として本体とは別に出します。

規程本体だけでは届出できないので、次の3つを添えます。

- 決める必要がある項目（該当条つき）
- 別途作成が必要な規程（本則で「別に定める」と委任した先）
- 届出までの手順（専門家確認 → 意見聴取 → 届出 → 周知）

育児・介護休業まわりは、モデル就業規則ではなく
[育児・介護休業等に関する規則の規定例](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/000103533.html)
を使います。産後パパ育休・子の看護等休暇・柔軟な働き方の措置はモデル就業規則に入っていません。

---

## 点検（work-regulations-check）

Word・PDF・テキストの就業規則を渡すと、次の4つの観点でレポートを作ります。

- **必須記載事項の漏れ** — 労基法89条の絶対的／相対的必要記載事項
- **違法・リスクのある条項** — 減給の上限、賠償予定、年休の許可制、固定残業代、65歳雇用確保など
- **法改正への未対応** — 2019年の働き方改革関連法以降の改正
- **形式面の不整合** — 条番号の飛び・重複、参照先のない「第○条」、用語のゆれ

## 特徴：根拠を原典から引く

法令チェックで一番こわいのは、条番号や割増率をそれらしく間違えることです。
このスキルは**記憶で根拠を書かず、必ず原典を取得**します。

```
厚労省の改正情報        何が・なぜ変わるか、義務／努力義務の別、施行期日
       ↓                厚生労働省 国会提出法案の概要PDF
e-Gov で現行法を確認    条文の原文（そのまま引用できる文言）
       ↓                e-Gov法令API
施行日を確認            いま効いているのか、これから効くのか
       ↓                未施行の改正を自動検出し、--asof で先読み
就業規則への影響を判定  どの条を、どう直す必要があるのか
```

修正案は、厚生労働省「モデル就業規則」の規程例から引いて作ります。
自作の条文より、労基署への説明や社内の承認が通りやすいためです。

### 条番号のずれを踏む事故を防ぐ

改正で条が挿入されると、以降の条番号が繰り下がります。たとえば労働施策総合推進法の第33条は、

| 版 | 中身 |
|---|---|
| 現行（2026年4月1日施行） | 厚生労働大臣による助言・指導・勧告 |
| 2026年10月1日施行 | 顧客等の言動に起因する問題に関する措置（カスハラ） |

`--asof` を付けずに現行版で引くと、まったく別の条文を根拠として書いてしまいます。
スキルは未施行の改正を検出して警告します。

## インストール

```
/plugin marketplace add Ebi-lock/work-regulations-check
/plugin install work-regulations-check@work-regulations-check
```

## 使い方

話しかけるだけです。

**作る**

```
就業規則を作りたい
従業員が10人になるので就業規則を用意したい
育児介護休業規程を新しく作って
```

**点検する**

```
就業規則.pdf をチェックして
この規程、法改正に対応できてる？
育児介護休業規程の条番号がおかしくないか見て
```

## 同梱しているもの

| スクリプト | 役割 |
|---|---|
| `extract_text.py` | Word/PDF/RTF からテキスト抽出。docxは表とヘッダーフッター、PDFはページヘッダー除去に対応 |
| `check_structure.py` | 条文の地図を作り、条番号の飛び・重複・参照切れ・存在しない項への参照を検出。内部参照の解決先を一覧表示し、条番号は合っているが中身が違う参照を目視で見つけられるようにする |
| `fetch_law.py` | e-Gov法令APIから条文を取得。施行日の確認、未施行の改正の検出、`--asof` での先読み |
| `mhlw_bills.py` | 厚労省の国会提出法案から改正の概要PDFを取得 |
| `model_rules.py` | 厚労省の規程例から条文案と解説を引く。モデル就業規則と育児・介護休業等の規定例の両方に対応 |

2つのスキルはスクリプトを共有しています（`skills/work-regulations-draft/scripts` は
`work-regulations-check/scripts` へのシンボリックリンク）。片方だけ更新される事故を防ぐためです。

参照ファイル（`references/`）に、必須記載事項のチェックリスト、リスク条項のパターン集、
法改正の一覧と判定手順、根拠の引き方、聞き取り項目、章立てと別規程の切り分けをまとめてあります。

## 動作要件

- Python 3.8 以上（標準ライブラリのみで大半が動きます）
- **Word (.docx) を読む場合**: `pip3 install python-docx`
- **PDF を読む場合**: `pip3 install pypdf`（無い場合は Claude の Read ツールで直接読みます）
- **.doc / .rtf を読む場合**: macOS の `textutil`（OS標準）
- ネットワーク接続（e-Gov・厚労省へのアクセス）

## 通達も引きたい場合（任意）

条文だけでは運用が決まらないことが多く、行政解釈は通達に出ます。通達は e-Gov にありません。
[`labor-law-mcp`](https://www.npmjs.com/package/labor-law-mcp) を入れると、
厚労省法令等データベースと安全衛生情報センター（JAISH）の通達を引けるようになります。

```
claude mcp add labor-law -s user -- npx -y labor-law-mcp
```

スキルは MCP の有無を見て動きを変えます。入れなくても動作します（通達を根拠にしたい指摘が
「要確認」に回るだけです）。

なお、これは第三者が公開しているパッケージです。導入は各自の判断で行ってください。

## 免責

**このプラグインの出力は法的助言ではありません。**

作成したものは**社労士・弁護士に確認してもらうための下書き**、点検結果は
**相談前の一次スクリーニング**として作られています。
レポートには根拠となる条文と施行日を必ず併記するようにしていますが、次の限界があります。

- 法改正は頻繁にあり、参照ファイルの一覧は基準日時点のものです。スキルは実行時に
  厚労省・e-Gov を確認しますが、通達・告示・指針・判例まで網羅するものではありません
- 事業場の規模・業種・雇用形態によって結論が変わる項目があり、それらの情報が不明な場合は
  「要確認」として出力されます
- 規程の文面だけを見ており、実際の運用実態は考慮していません

**実際の就業規則の作成・変更にあたっては、必ず社会保険労務士または弁護士の確認を受けてください。**
就業規則の作成・変更の代行は社会保険労務士の業務に関わります。このスキルは検討材料を
用意するものであって、専門家による確認に代わるものではありません。

出力内容に起因する損害について、作者は責任を負いません。
