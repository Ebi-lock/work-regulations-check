# 根拠の引き方（厚労省・e-Gov法令検索・モデル就業規則）

指摘の根拠は、記憶ではなく原典から引く。条番号・割増率・日数・人数要件は
記憶で書くと高い確率でずれる。ずれた根拠を書いたレポートは、専門家に見せた瞬間に信用を失う。

原典は3つあり、役割が違う。

| 出典 | 分かること | 分からないこと |
|---|---|---|
| 厚労省の改正資料 | 何が・なぜ・いつから変わるか。義務／努力義務の別 | 条文の正確な文言 |
| e-Gov法令検索 | 条文の原文、いま効いている版、施行日 | 何が新しいのか、なぜ入ったのか |
| モデル就業規則 | 規程に落とすときの文言 | 法令上の要否（規程例と違う＝違反ではない） |

法改正まわりは `references/amendments.md` の4ステップに従うこと
（厚労省 → e-Gov → 施行日 → 影響判定）。このファイルは各出典の使い方をまとめたもの。

## 0. 改正情報は厚労省から取る

```bash
python3 scripts/mhlw_bills.py --sessions       # 掲載されている国会回次
python3 scripts/mhlw_bills.py --session 217    # その回次の労働関係法案と資料URL
python3 scripts/mhlw_bills.py --summary 217    # 概要PDF（改正のポイントと施行期日）
python3 scripts/mhlw_bills.py --recent 3       # 直近3回次
```

概要PDFには改正の趣旨、項目ごとの内容、施行期日が1枚にまとまっている。
「義務付け」「努力義務」「責務」の書き分けもここで読む。
概要で足りなければ、同じ一覧の**新旧対照条文**でどの条がどう変わったかを確認する。

告示・指針（パワハラ指針など）は法案資料に含まれない。「就業規則にどう書くか」は
指針に書かれていることが多いので、必要なら厚労省サイトを WebSearch で探す。

## 1. 条文は e-Gov法令検索から引く

https://laws.e-gov.go.jp/ の公式APIを `scripts/fetch_law.py` から叩く。

```bash
python3 scripts/fetch_law.py --list                 # 引ける法令の一覧
python3 scripts/fetch_law.py 労基法 89 91 37        # 条文を取得
python3 scripts/fetch_law.py 労基法 --status        # 現在の施行日と最終改正
python3 scripts/fetch_law.py 育介法 --grep 看護     # 本文検索して該当条を出す
python3 scripts/fetch_law.py 労施法 33 --asof 2026-10-01   # 未施行の改正後の条文
```

出力の先頭に **現在の版の施行日と最終改正** が出る。レポートで「〜法第○条」と書くときは、
この施行日を見て、いま有効な条文を引いていることを確認する。

### `--asof` を使う場面

就業規則は施行日を迎えてから直すのでは遅い。改定作業には意見聴取と届出が要るので、
**数か月先に施行される改正は、いま織り込むべき指摘** になる。
`--status` に「★ 未施行の改正あり」と出たら、その日付で `--asof` を付けて条文を取り直し、
「いつから何が変わるか」をレポートに書く。

### 引ける法令

労基法 / 労基則 / 労契法 / 育介法 / 高年法 / 労施法（パワハラ・カスハラ）/
パート有期法 / 均等法 / 安衛法 / 最賃法

一覧にない法令は、e-Gov で法令IDを調べて `--law-id` で直接指定する。
法令IDは e-Gov の法令ページURL末尾（例: `https://laws.e-gov.go.jp/law/322AC0000000049`）。

### e-Gov で取れないもの

ここを取り違えると、根拠として成立しない指摘になる。

| 種類 | 例 | どうするか |
|---|---|---|
| 政令・省令の細目 | 割増賃金令、労基則の様式 | 労基則は `労基則` で引ける。政令は法令IDを調べて `--law-id` |
| 告示・指針 | パワハラ指針、同一労働同一賃金ガイドライン | e-Gov にはない。厚労省サイトを WebSearch で確認する |
| 通達 | 基発・基収 | e-Gov にはない。**labor-law MCP があればそれで引く**（下記）。無ければ厚労省法令等DBを WebSearch |
| 判例 | 解雇権濫用、固定残業代の要件 | e-Gov にはない。判例名と裁判所・年月日を書く |
| 改正法の経過措置 | 「当分の間、常時○人未満の事業場には適用しない」 | 本体ではなく**改正法の附則**にあることがある。本体を引いて見つからないときは、改正法を別途引くか WebSearch で確認する |

判断が付かないときは「要確認」に回す。根拠を示せない指摘は書かない。

## 1-2. 通達は labor-law MCP から引く

通達（基発・基収など）は、条文の解釈を行政がどう示しているかを表す。
「法第○条をどう運用するのか」は条文だけでは決まらず、通達で初めて分かることが多い。
e-Gov にはないため、`labor-law` MCP が使えるならそれで引く。

| ツール | 用途 |
|---|---|
| `mcp__labor-law__search_mhlw_tsutatsu` | 厚労省法令等DBを通達のキーワード検索 |
| `mcp__labor-law__get_mhlw_tsutatsu` | 通達本文を取得（検索結果の `data_id` を渡す） |
| `mcp__labor-law__search_jaish_tsutatsu` | 安全衛生関係の通達を検索（JAISH） |
| `mcp__labor-law__get_jaish_tsutatsu` | 安衛通達の本文を取得（`url` を渡す） |
| `mcp__labor-law__get_law` | 条文取得。45法令のプリセットと略称に対応 |
| `mcp__labor-law__search_law` | 法令名が分からないときの横断検索 |

MCP が使えない環境なら `scripts/fetch_law.py` で代替する（通達は引けないので、
通達を根拠にしたい指摘は「要確認」に回す）。

### 通達検索のコツ

キーワードは AND 検索で、語を増やすと逆に外れる。**2語までに絞る。**
「就業規則 減給 制裁」のように3語入れると無関係な健保の事務連絡が並ぶ一方、
「年次有給休暇 時季指定」のように的を絞ると、基発1228第15号
（働き方改革関連法による改正後の労働基準法関係の解釈について）のような本命に当たる。

外れたら、法律名＋制度名（「労働基準法 時間外」）や、改正法の名前で引き直す。
数回試して出てこなければ、通達を根拠にするのは諦めて条文だけで書く。

### よく使う通達

| 通達 | 内容 |
|---|---|
| 基発1228第15号（平成30年12月28日） | 働き方改革関連法による改正後の労基法の解釈。**年5日の時季指定義務のQ&A**、時間外上限規制の解釈 |
| 発基第17号（昭和22年9月13日） | 労働基準法の施行に関する件。減給の制裁など基本的な解釈の出発点 |

## 2. 修正案は厚労省「モデル就業規則」に合わせる

`scripts/model_rules.py` が厚労省の最新版 docx を取得して規程例を引く。

```bash
python3 scripts/model_rules.py --toc                  # どんな条があるか
python3 scripts/model_rules.py --grep 年次有給休暇     # 規程例
python3 scripts/model_rules.py --article 23           # 条番号で引く
python3 scripts/model_rules.py --grep 懲戒 --explain  # 規程例＋厚労省の解説
python3 scripts/model_rules.py --version-info         # 版と出典URL
```

条文案を自分の言葉で作るより、規程例をベースに事業場の実情に合わせて調整するほうがよい。
文言が厚労省のものであれば、労基署に出したときに説明がしやすく、
人事担当者が社内で承認を取るときにも通しやすい。

`--explain` で出る解説には、その規定を置く理由と法令上の要求が書かれている。
レポートの「問題」欄を書くときの材料になる。

**ただしモデル就業規則は一例であって、これに合わせること自体は義務ではない。**
「モデル就業規則と違う」だけを理由に指摘してはいけない。指摘するのは、
法令に反しているか、法令が求める記載が無い場合に限る。
モデル就業規則は「あるべき姿の参考」ではなく「条文案の供給元」として使う。

### 版について

スクリプトは執筆時点の版（令和7年12月版）の docx URL を直接叩いている。
改訂されると URL の数字が変わるため、ダウンロードに失敗したら
掲載ページで最新版を確認してスクリプトの `DOCX_URL` を直す。

掲載ページ:
https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/koyou_roudou/roudoukijun/zigyonushi/model/index.html

育児・介護休業関係は本体に含まれない部分があるため、必要なら
厚労省が別に公開している「育児・介護休業等に関する規則の規定例」を WebSearch で探す。

## 3. レポートへの書き方

根拠は、条番号だけでなく **確認した日と施行日** まで書くと、後から読む人が
そのまま使える。

```markdown
**根拠**: 労働基準法第91条（2026年7月17日施行の版で確認。e-Gov法令検索）
> 就業規則で、労働者に対して減給の制裁を定める場合においては、その減給は、
> 一回の額が平均賃金の一日分の半額を超え、総額が一賃金支払期における賃金の
> 総額の十分の一を超えてはならない。

**修正案**: 厚生労働省「モデル就業規則」令和7年12月版 第67条（懲戒の種類）に準拠
```

条文の引用は、`fetch_law.py` の出力をそのまま貼る。要約して引用すると、
「〜を超えてはならない」が「〜まで」になるような、意味の変わる崩れが起きる。
